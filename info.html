1. SOFTWARE SPECIFICATION

Key Tasks

  • Feasibility Study - Determine whether the proposed web-based student medical information system is practical and suitable for College of Saint Lawrence.
  • Requirements Elicitation and Analysis - Identify and analyze the needs of students and authorized school personnel for recording medical information and submitting supporting documents.
  • Requirements Specification - Define the system's required functions, including medical information recording, document submission, record management, and controlled access.
  • Requirements Validation - Verify that the requirements are complete, consistent, and appropriate for the proposed system

2. SOFTWARE DESIGN AND IMPLEMENTATION

Design Activities

  • Architectural Design - Design the overall structure of the web-based medical information system and determine how students, authorized personnel, and the database interact.
  • Abstract Specification - Define the system components for managing student medical information and supporting medical documents.
  • Interface Design - Design the student interface for entering medical information and uploading medical certificates or doctor reports, as well as the authorized personnel interface for viewing records.
  • Component Design - Design separate components for student accounts, medical information, document submission, record management, and access control.
  • Data Structure Design - Design the database structure for student medical records, medical conditions, physical limitations, previous surgeries, and submitted documents.
  • Algorithm Design - Design the procedures for saving, updating, retrieving, uploading, and accessing medical information and documents according to user roles.

Implementation

  • Translate Design into Program - Convert the designed system structure, interfaces, database, and components into the actual web-based system.
  • Programming and Debugging - Program the system functions and identify and correct errors in medical information recording, document submission, account management, and access control

3. SOFTWARE VALIDATION

Testing Stages

  1. 1. Unit Testing - Test individual functions, such as adding medical information, updating a record, uploading a document, and logging in.
  2. 2. Module Testing - Test related functions together, such as the student medical information module and document submission module.
  3. 3. Sub-system Testing - Test integrated sections, such as the student side working together with the authorized personnel side and database.
  4. 4. System Testing - Test the entire web-based medical information system to ensure that all functions work together correctly and that access restrictions work as intended.
  5. 5. Acceptance Testing - Have the intended users, particularly students and authorized school personnel, test the system to determine whether it meets the requirements.

4. SOFTWARE EVOLUTION

Key Tasks

  • Correct Errors - Identify and correct errors found in the system, such as problems with recording medical information, uploading documents, or accessing records.
  • Improve Performance - Improve the system's speed, reliability, and efficiency when managing student medical information and supporting documents.
  • Adapt to New Requirements - Modify the system when the school has new requirements for managing student medical information or document submission.
  • Add New Features - Add useful features that may be needed in the future to improve medical information management.
  • Reconfigure for New Environments - Modify or configure the system when changes in the school's technical environment require it.
